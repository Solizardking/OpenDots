# Pump.fun in Solana Dots 0.2.2

Pump.fun launches and trades can use a connected browser wallet or the encrypted OWS wallet assigned to a Dot in the local Mac binary. Open **Wallet** to connect a Wallet Standard compatible Solana wallet, see its address and balance, or disconnect. Your registration account and transaction signing wallet are displayed separately; using a secondary wallet does not relink your account. Connecting authorizes no transactions. Fund the signing wallet with SOL for network fees, account rent and SOL buys. For a coin quoted in another asset, also fund that quote asset.

Open **Pump.fun** from the workspace sidebar or chat header. The global panel creates or reuses a private Pump.fun conversation without requiring a model provider. Select **Connected browser wallet**, or use **Encrypted Dot wallet** after creating/selecting one in Dot settings and saving the Dot. **Launch coin** accepts a name, symbol and public metadata JSON URI (`https://`, `ipfs://` or `ar://`). The JSON should contain the coin image and description. It creates a standard SOL-paired Token-2022 coin with the selected wallet as payer and creator. An optional initial SOL buy is included atomically. Optional holder rewards permanently direct creator fees to holders; new cashback and mayhem launches are excluded from this flow.

For **Buy** or **Sell**, enter the exact mint and choose **Inspect coin & balance**. Inspection shows the actual quote asset, token balance and bonding curve or PumpSwap venue. Buy amounts use quote asset units; sell amounts use base token units. Slippage accepts 0–20% in 0.1% steps. The app detects legacy SPL Token versus Token-2022 and uses the actual mint decimals.

You can also ask in normal chat:

- “Inspect this Pump.fun mint: `<mint>`.”
- “Prepare a launch for Example, symbol EX, using metadata `ipfs://…`, with a 0.01 SOL initial buy.”
- “Prepare a buy of 0.01 SOL of `<mint>` with 1% slippage.”
- “Prepare a sale of 100 tokens of `<mint>` with 1% slippage.”

The model prepares a proposal and invokes `review_pump_transaction`. Supply the public connected signing address when using browser wallets. The review card loads the server's stored transaction rather than accepting the model's amounts. It shows the wallet, mint, quote asset, maximum spend, minimum receive, fees, simulated SOL debit including rent, expiry, exact instruction accounts and transaction bytes. Protocol and creator fees are included in the quote; this Pump panel adds no application fee.

For a connected wallet, check the review checkbox, then choose **Review in wallet & submit**. The connected adapter must match the reviewed payer, and signing happens entirely in the wallet. The server accepts only the original reviewed message with all valid signatures, including the preserved mint signature on launches. Closing a review during wallet approval prevents submission. Editing the mint, amounts, slippage, metadata, launch options or signing wallet clears and declines the prior proposal and requires fresh preparation.

For the encrypted local Dot wallet, enter its passphrase or scoped OWS token in the card, check the review checkbox, then choose **Approve & submit**. Credentials go directly to the local wallet signer and are cleared from the form; they do not enter model messages, transaction records or logs. OWS policy checks remain enforced. Hosted workspaces cannot unlock local OWS wallets.

Proposals expire after 75 seconds or their blockhash validity ends. A fresh proposal supersedes the previous unapproved one in that conversation. Approval also checks the current wallet assignment, workspace pause state and mainnet genesis hash. Requests are bound to the owning conversation and to the hash of the exact reviewed transaction. The generated mint signs locally; OWS signs the complete serialized transaction; both signatures are verified before broadcast. No wallet private key is exported.

The durable SQLite receipt distinguishes **prepared**, **signing**, **submitted**, **confirmed**, **failed**, **expired** and **declined**. The app polls a submitted signature for confirmation, including after restart. Duplicate approval never signs or broadcasts again. A network error during submission remains uncertain until the signature can be checked; it is not shown as a confirmed trade. The transaction link opens Solscan. Phone companions can chat but cannot invoke these wallet approval routes.

An optional **Solana mainnet RPC** connection in Settings is stored with macOS Keychain encryption, including any provider credential in its URL. The default is `https://api.mainnet-beta.solana.com`. Every preparation and approval verifies the full mainnet genesis hash. Wallet balances use the configured server RPC through an authenticated read-only endpoint, including while the workspace is paused. Lamports and SOL balances return as precise decimal strings. Provider URLs stay server-side.
